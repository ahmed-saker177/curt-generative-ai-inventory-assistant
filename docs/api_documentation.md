# 📡 CURT Inventory Assistant — API Documentation

This document describes the REST API endpoints provided by the CURT Inventory Assistant FastAPI backend.

The backend exposes endpoints for operational health checks, raw inventory queries, and conversational agent interactions powered by LLMs (Groq or Google Gemini) with schema-validated tool calling.

---

## 📋 Endpoints Summary

| Method | Endpoint | Description | Auth Required |
| :--- | :--- | :--- | :--- |
| `GET` | `/health` | Operational health check & SQLite readiness | No |
| `GET` | `/inventory` | List all parts currently in SQLite database | No |
| `POST` | `/chat` | Send a natural language query in a persistent session | No |

## 1. `GET /health`

Checks if the FastAPI server is running and the SQLite database connection is operational.

### Request
```http
GET /health HTTP/1.1
Host: localhost:8000
Accept: application/json
```

### Response
- **Status:** `200 OK`
- **Content-Type:** `application/json`

```json
{
  "status": "ok",
  "inventory_ready": true
}
```

### Schema (`HealthResponse`)
| Field | Type | Description |
| :--- | :--- | :--- |
| `status` | `string` | Service status (e.g. `"ok"`) |
| `inventory_ready` | `boolean` | `true` if SQLite database was initialized and is accessible |

---

## 2. `GET /inventory`

Retrieves all cataloged motorsport inventory items from the shared SQLite database.

### Request
```http
GET /inventory HTTP/1.1
Host: localhost:8000
Accept: application/json
```

### Response
- **Status:** `200 OK`
- **Content-Type:** `application/json`

```json
[
  {
    "id": 1,
    "name": "Brake Pads",
    "quantity": 12,
    "category": "Brakes",
    "location": "Mechanical Workshop"
  },
  {
    "id": 2,
    "name": "Brake Discs",
    "quantity": 6,
    "category": "Brakes",
    "location": "Mechanical Workshop"
  },
  {
    "id": 3,
    "name": "ECU",
    "quantity": 2,
    "category": "Electronics",
    "location": "Electronics Lab, Shelf B"
  }
]
```

### Schema (`InventoryItem`)
| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `integer` | Primary key identifier |
| `name` | `string` | Component name |
| `quantity` | `integer` | Current stock count (units) |
| `category` | `string` | FSAE subsystem (e.g. `Brakes`, `Electronics`, `Chassis`) |
| `location` | `string` | Storage shelf, workshop, or room |

## 3. `POST /chat`

Conversational assistant endpoint. It accepts user questions in plain natural language, orchestrates the LLM agent loop (calling backend tools like `check_stock`, `list_low_stock`, etc.), and maintains multi-turn conversation history per `session_id`.

### Request Headers
```http
POST /chat HTTP/1.1
Host: localhost:8000
Content-Type: application/json
Accept: application/json
```

### Request Body (`ChatRequest`)
```json
{
  "message": "How many brake pads do we have left, and where are they stored?",
  "session_id": "c7a840e6-5c21-4f76-88da-d11234567890"
}
```

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `message` | `string` | **Yes** | Natural language user message (1 to 2,000 characters). |
| `session_id` | `string` | No | Optional session UUID. If omitted, the backend generates a new UUID. Pass the returned `session_id` in subsequent requests for multi-turn context. |

### Successful Response (`ChatResponse`)
- **Status:** `200 OK`
- **Content-Type:** `application/json`

```json
{
  "session_id": "c7a840e6-5c21-4f76-88da-d11234567890",
  "response": "We currently have 12 Brake Pads in stock, stored in the Mechanical Workshop.",
  "provider": "groq",
  "tools_used": [
    "check_stock"
  ]
}
```

| Field | Type | Description |
| :--- | :--- | :--- |
| `session_id` | `string` | Active session UUID for continuing the conversation. |
| `response` | `string` | Final natural language answer generated by the assistant. |
| `provider` | `string` | Active LLM provider (`groq` or `gemini`). |
| `tools_used` | `array[string]` | List of backend Python tools invoked during the agent loop. |

## 🚨 Error Responses

### `422 Unprocessable Entity` (Validation Error)
Returned when the request payload is malformed or violates constraints (e.g., empty message).

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "message"],
      "msg": "String should have at least 1 character",
      "input": ""
    }
  ]
}
```

### `502 Bad Gateway` (LLM Provider Error)
Returned when the external LLM provider (Groq or Gemini) fails, times out, or returns an unparseable response.

```json
{
  "detail": "LLM provider runtime failure: Rate limit exceeded"
}
```

### `503 Service Unavailable` (Configuration Error)
Returned if API keys are missing or invalid in `.env`.

```json
{
  "detail": "GROQ_API_KEY environment variable is not set."
}
```

## 💻 Code Examples

### cURL

#### 1. Check Health
```bash
curl -X GET "http://localhost:8000/health"
```

#### 2. Query Full Inventory
```bash
curl -X GET "http://localhost:8000/inventory"
```

#### 3. Ask a Question (New Session)
```bash
curl -X POST "http://localhost:8000/chat" \
  -H "Content-Type: application/json" \
  -d '{"message": "How many ECUs are left?"}'
```

#### 4. Ask a Follow-Up (Existing Session)
```bash
curl -X POST "http://localhost:8000/chat" \
  -H "Content-Type: application/json" \
  -d '{
    "message": "Where is it stored?",
    "session_id": "c7a840e6-5c21-4f76-88da-d11234567890"
  }'
```

### Python (`requests`)

```python
import requests

BASE_URL = "http://localhost:8000"

# 1. First question
response = requests.post(
    f"{BASE_URL}/chat",
    json={"message": "Do we have brake pads in stock?"}
)
data = response.json()
print("Assistant:", data["response"])
print("Tools executed:", data["tools_used"])

session_id = data["session_id"]

# 2. Multi-turn follow-up using the same session_id
follow_up = requests.post(
    f"{BASE_URL}/chat",
    json={
        "message": "What about brake discs?",
        "session_id": session_id
    }
)
print("Follow-up Assistant:", follow_up.json()["response"])
```
